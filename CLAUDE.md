# CLAUDE.md

Guidance for working in the Pisaka repository.

## What this is

Pisaka is a native code editor (MVP 0.1) for **macOS, iPad, and iPhone**. The
domain logic lives in a Foundation-only `PisakaCore` SwiftPM library shared
across all platforms; the app itself is a single multiplatform Xcode target
(macOS 13 + iOS 17) generated by XcodeGen from `project.yml`. There is no longer
a SwiftPM executable — `swift run Pisaka` is gone. See `README.md` for the
user-facing feature list and shortcuts.

## Build & project layout

The app target is built through the XcodeGen-generated Xcode project, *not*
`swift build`/`swift run`:

- `project.yml` (XcodeGen) declares one application target with
  `supportedDestinations: [macOS, iOS]` (the modern Xcode multiplatform app —
  one target, multiple destinations) and pins every *remote* dependency to the
  exact version/revision the committed workspace `Package.resolved` records; two
  tree-sitter grammars are instead local `path:` dependencies under `Vendor/`
  and so carry no pin (see Conventions).
  `xcodegen generate` produces `Pisaka.xcodeproj`; build with Xcode or
  `xcodebuild -scheme Pisaka -destination …`.
- `Vendor/` — two self-contained tree-sitter grammar SwiftPM packages
  (`TreeSitterGitignore`, `TreeSitterDotenv`) consumed by the app target as
  `path:` dependencies from `project.yml`, each with a `VENDORED.md` recording
  the upstream SHA, what is verbatim vs. authored here, and the by-hand update
  procedure (Conventions covers the two different reasons they are vendored).
  Each builds in isolation (`swift build --package-path Vendor/<name>`); the
  root `Package.swift` does not reference them, so `swift test` stays
  dependency-free.
- `Package.swift` builds *only* the platform-agnostic `PisakaCore` library
  (exposed as a `.library` product so the Xcode project can consume it from the
  local package) and its test target, so `swift test` stays the fast,
  dependency-free gate for the domain logic — compiled for the host and (per the
  Phase 0 audit) source-compatible with iOS. All external dependencies and their
  pins live in `project.yml`; `PisakaCore` and the tests stay dependency-free.
- Per-platform dependency split: Neon/SwiftTreeSitter/Rearrange + the
  tree-sitter grammars link on all platforms; **SwiftTerm** (embedded terminal)
  is used only by macOS-gated code; **libgit2** (`ibrahimcetin/libgit2`, built
  from C source so every Apple destination gets a natively-compiled slice — no
  binary-xcframework slice-coverage problem) is used only by iOS-gated code. A
  single multiplatform target links every SPM product into every destination
  (package-product deps are all-or-nothing per target, not per-destination
  filterable), so SwiftTerm links as unused dead weight on iOS and libgit2 links
  as unused dead weight on macOS; the *real* restriction is enforced at the
  source level with `#if os(macOS)` / `#if os(iOS)`.

## Architecture

The project keeps all logic in `PisakaCore` so it is testable without a UI; the
platform view layers (`Sources/Pisaka/`, AppKit/SwiftUI on macOS and
UIKit/SwiftUI on iOS) are thin and untested.

**Per-file design docs live in `docs/architecture/`.** Every file's detailed
contract — invariants, edge cases, and the reasoning behind non-obvious
decisions — lives there (moved verbatim out of this file, which holds only this
index). **Before modifying a file, read its entry in the doc named beside it
below, and update that entry when you change behavior.**

### Cross-cutting invariants (details in the docs above)

- **Generation tokens**: every async git/search model orders overlapping work by
  monotonic tokens captured *synchronously* before the `Task` hop
  (`prepareForFolderChange`/`prepareForRefresh` return them; mutations take
  `originGeneration`); superseded work discards its result instead of
  publishing over newer state.
- **Disk-writer coordination**: every git-mutating operation (revert, merge
  apply, branch switch/create, project Replace All, commit) raises
  `autosave.suspend()` + `localChanges.beginRevert()` synchronously before its
  first `await` (balanced by `defer`); the project-tree file ops, ⌘S and the
  run/test saves refuse while the gate is up.
- **Open-tab resync** after an operation rewrites the worktree: buffers are
  snapshotted before the hop; a clean, unchanged tab gets `reloadFromDisk`, an
  edited one `reconcileSavedBaseline` + beep, a deleted file force-closes
  (except after a commit, which never deletes worktree files).
- **Pure engine + thin glue**: every decision lives in Core and is unit-tested;
  views only wire triggers to engines and are untested.
- **Paths**: store as the user spelled them, match canonically
  (`CanonicalPath`); the FSEvents watcher alone uses `realpath(3)` — the two
  must not be unified (documented on both).
- **Line separators**: the editor splits on LF/CR/CRLF/NEL/LS/PS everywhere via
  `LineStartIndex`/`TerminatedLines`; git speaks LF only — `BlameAlignment`
  bridges — and regex `^`/`$` follow ICU's superset (known limit).

## Tests

Unit tests live in `Tests/PisakaCoreTests/` and cover `PisakaCore` only (the UI
layer is intentionally thin). Test the logic in `WorkspaceModel`/`FileService`,
not the SwiftUI views.

## Commands

```sh
swift test            # run the PisakaCore test suite (all platforms)

# The app target is built through the XcodeGen project, not `swift build`/`run`:
xcodegen generate     # regenerate Pisaka.xcodeproj from project.yml
xcodebuild -project Pisaka.xcodeproj -scheme Pisaka -destination 'platform=macOS' build
xcodebuild -project Pisaka.xcodeproj -scheme Pisaka \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

CI (`.github/workflows/ci.yml`) runs these same gates on every pull request and
push to `master`: `swift test` first, then — only when it is green — an unsigned
macOS build and an unsigned iOS build (device arch, `generic/platform=iOS`,
covering libgit2 linking) in parallel. No signing, secrets, or simulator.

## Conventions

- Keep all domain logic in `PisakaCore`; keep the `Pisaka` app views thin
  (macOS files under `#if os(macOS)`, iOS files in `Sources/Pisaka/iOS/`).
- Every behavioral change must come with new/updated `PisakaCore` tests, and the
  full suite must pass before moving on.
- External dependencies are confined to the `Pisaka` app target only, declared
  and pinned in `project.yml` (the SwiftPM manifest stays dependency-free):
  ChimeHQ's Neon (which brings in `SwiftTreeSitter`/`Rearrange`) plus one
  tree-sitter grammar package per supported language, for syntax highlighting on
  all platforms; SwiftTerm (migueldeicaza/SwiftTerm, the PTY-backed
  `LocalProcessTerminalView`) for the macOS-only embedded terminal; and libgit2
  (`ibrahimcetin/libgit2`, built from C source) for the iOS in-process
  `GitServicing`. All *remote* ones are pinned to an exact version/revision
  (e.g. SwiftTerm `exact: "1.5.0"`, libgit2 `exact: "1.9.2"`, the Dockerfile
  grammar `camdencheek/tree-sitter-dockerfile` `exact: "0.2.0"`), with build
  reproducibility locked
  by the committed workspace `Package.resolved` — which is written in SwiftPM's
  v2 schema (`identity`/`kind`/`location`), the form `xcodebuild
  -resolvePackageDependencies` and CI produce; a commit that rewrites the whole
  file into the legacy v1 shape (`object.pins`/`repositoryURL`) is format churn
  hiding the real pin change and should be re-generated rather than reviewed.
  The two vendored grammars are the exception to the pinning rule: they are
  local *path* dependencies pinned by their directory contents (next bullet).
  `PisakaCore` and the test
  target stay dependency-free and must never import
  Neon/SwiftTreeSitter/SwiftTerm/libgit2/AppKit/UIKit/CoreServices (the FSEvents
  watcher is view-layer only; its one decision lives in Core as the Foundation-only
  `TreeRefreshFilter`) — keep them on the Apple
  SDK (Foundation only) so the domain logic stays portable and testable. See the
  pinning notes in `project.yml`/`Package.swift` for why specific revisions/tags
  are chosen.
- Two tree-sitter grammars are **vendored** as local SwiftPM path dependencies
  under `Vendor/` instead of being pinned remotely, for two *different* reasons.
  A path dependency carries no `Package.resolved` pin (the directory content is
  the pin), and each one keeps a `VENDORED.md` recording the upstream URL, the
  exact SHA and date, the license, what is verbatim vs. authored here, and a
  step-by-step by-hand update procedure.
  `Vendor/TreeSitterGitignore` (upstream `shunsambongi/tree-sitter-gitignore`,
  MIT, SHA `f4685bf…`) exists because there is *nothing to depend on remotely*:
  upstream publishes no SwiftPM manifest, no `bindings/swift` header and no
  `queries/highlights.scm`, so only `src/`, `grammar.js` and `LICENSE` are
  copied and **the manifest, the Swift binding header and the highlight query are
  written in this repo**. That last file is why this package has a *mandatory
  verification recipe* (kept in its `VENDORED.md`, with fixtures and the confirmed
  element-by-element capture table) that must be re-run on **every** grammar
  update: both failure modes of a hand-written query are silent in the app — an
  unknown *node* name fails query compilation, so `LanguageConfiguration` throws,
  `makeConfiguration` returns `nil`, and the file quietly degrades to plain text;
  a mistyped *capture* name compiles fine and resolves to `SyntaxTokenKind.plain`,
  i.e. default-colored text. Neither is caught by "the file looks highlighted",
  so the *static* half of that recipe is additionally automated in Core as
  `VendoredGrammarQueryTests` (Foundation-only, reading the vendored files
  themselves through `#filePath`): for **both** in-repo queries it asserts that
  every node name and anonymous literal the `.scm` uses is declared in that
  grammar's own `src/node-types.json` **under the matching `named` flag** — the
  check that catches a typo, a node a grammar update renamed, or one whose
  `named` status it flipped, before any of them ships as plain text. The named
  and anonymous types are read as *two* sets rather than merged into one,
  because the wrong spelling (`"comment"` for a named node, `(digit)` for an
  anonymous token) fails `ts_query_new` with `TSQueryErrorNodeType` exactly as an
  unknown name does, and gitignore declares 18 anonymous tokens that read like
  ordinary node names (`digit`, `alpha`, `space`, …), so a merged lookup would
  wave through a query that cannot compile — the very failure the suite exists to
  catch. It also asserts that the set of
  capture names it emits is *exactly* the expected one, each resolving to a
  non-`.plain` `SyntaxTokenKind`. Set equality is the point: a query that gains
  a capture fails the suite until someone confirms the Core mapping covers it.
  What stays manual is the *runtime* half (that the query compiles against the
  grammar and that every element of a fixture is actually captured), which needs
  SwiftTreeSitter — deliberately not linked by Core — so the `VENDORED.md`
  harness recipe remains mandatory on every grammar update. The remote
  dockerfile grammar's query is not in this repository and so cannot be read;
  its capture names stay pinned by hand in `SyntaxTokenKindTests`.
  `Vendor/TreeSitterDotenv` (upstream `pnx/tree-sitter-dotenv` v1.1.1, MIT,
  SHA `8b1dad8…`) exists for the narrower reason that **upstream's own manifest
  does not link**: the grammar declares an external scanner
  (`externals: [$._end_of_assignment]`) but its `Package.swift` `sources:` lists
  only `src/parser.c`, leaving a `// NOTE: if your language has an external
  scanner, add it here.` where `src/scanner.c` belongs, so the package compiles
  and then fails at link time in the consuming app with five undefined
  `tree_sitter_dotenv_external_scanner_*` symbols (the same omission is on
  upstream `main`, so no remote version links). The whole v1.1.1 tree is copied
  verbatim — including upstream's own `bindings/swift` header and
  `queries/highlights.scm` — and the only substantive local change is one line:
  `src/scanner.c` added to `sources:`. If upstream ever fixes their manifest,
  drop the directory and restore a remote `exactVersion` pin.
- A multiplatform Xcode target links every SPM product into every destination,
  so SwiftTerm links unused on iOS and libgit2 links unused on macOS; the actual
  platform restriction is enforced at the source level with
  `#if os(macOS)` / `#if os(iOS)`, not by dependency filtering.
- The iOS branch-switcher's network fetch is **HTTPS-only** (libgit2 over the
  built-in Apple TLS backend, PAT from the Keychain). SSH is out on iOS: this
  libgit2's SSH transport is `GIT_SSH_EXEC` (it execs the system `ssh` binary),
  and iOS has no subprocess, so an scp-style `git@…` / `ssh://` origin cannot be
  fetched — only an HTTPS `origin` works. No new dependency: HTTPS + TLS ship with
  the pinned libgit2, the PAT via the `Security` framework.
- Target platforms are macOS 13+ and iOS/iPadOS 17+.
- **Documentation placement**: this file must stay well under the 150k-char
  context limit (target ≈30k) — it carries only the index and the invariants
  above. Full per-file design rationale lives in `docs/architecture/*.md`.
  When behavior changes, update the matching entry there; a new file gets one
  index line here plus a full entry in the right doc. Never grow this file
  back into per-file essays.
