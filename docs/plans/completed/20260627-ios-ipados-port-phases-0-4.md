# iOS / iPadOS port (Phases 0–4)

## Overview

Bring Pisaka to iPad and iPhone as an adaptive SwiftUI/UIKit code editor with syntax highlighting, file access, and the git features (Local Changes, Log, conflict resolution) backed by libgit2 — sharing the existing Foundation-only `PisakaCore` across macOS and iOS. One multiplatform Xcode app target generated by XcodeGen (`project.yml`); `swift run Pisaka` goes away. The terminal stays macOS-only forever. Landed and verified phase-by-phase (0 → 4); each phase keeps the macOS app behaviour unchanged and `swift test` green.

## Context

- Files involved (existing, macOS-only today): everything in `Sources/Pisaka/` (AppKit views, `GitCLIService`, controllers). All gated to macOS in Phase 0.
- Reused as-is on iOS: all of `Sources/PisakaCore/` (models, parsers, `LineDiff`/`ThreeWayMerge`, `IndentEngine`/`AutoPairEngine`, `MinimapGeometry`/`MinimapModel`, `LineStartIndex`, `SettingsStore`, `BottomPanel`, the `GitServicing`/`FileServicing` protocols, and the observable models `WorkspaceModel`/`LocalChangesModel`/`CommitLogModel`/`MergeModel`).
- Build/config: `Package.swift` (currently one executable + library + tests), `Package.resolved` (dependency pins to preserve), no `project.yml` yet.
- Tests: `Tests/PisakaCoreTests/` — the testable surface; the UIKit/AppKit view layer stays untested per project convention.
- Related patterns to follow: protocol-behind-injectable-stub (`FileServicing`/`GitServicing`); domain logic in Core, thin platform views; `GitCLIService` as the real macOS `GitServicing` (the iOS libgit2 service is its peer).
- Dependencies: Neon/SwiftTreeSitter/Rearrange + tree-sitter grammars (all platforms), SwiftTerm (macOS-only), and new for Phase 2 — libgit2 for iOS.

## libgit2 decision (resolved)

- Phase 2 begins with a linking spike: prebuilt `Clibgit2`/static-libgit2 **xcframework** that links for both iOS device and simulator.
- Default: write the iOS `GitServicing` as a **direct C binding** against libgit2, for full control over the `revert`/conflict semantics the macOS CLI service implements.
- Only substitute a higher-level wrapper (e.g. SwiftGitX) if its iOS build is clean **and** it exposes every operation the protocol needs: stage blobs (`:N:path`), diff-tree vs first parent, and checkout/index flags.

## Development Approach

- **Testing approach**: Regular (code first, then tests). New Core logic gets `PisakaCoreTests`; the view/platform-wiring layer is not unit-tested per convention, but every phase must keep `swift test` green (now also compiled for iOS) and `xcodebuild` building both platforms.
- Land phase-by-phase; complete and verify each task before the next. The macOS app's behaviour must stay unchanged throughout.
- **CRITICAL: every task MUST include new/updated tests** where it adds Core logic; tasks that are pure view/platform wiring explicitly note when no Core test is needed.
- **CRITICAL: all tests must pass before starting the next task.**
- Per-task automatable gates: `swift test`, iOS Core compilation, and `xcodebuild` for both destinations. Manual simulator/device checks live in Post-Completion.

- [x] Implement the read/Local-Changes surface against libgit2: `repositoryRoot`, `changedFiles`, `headContents`/`blob`, building the **same** `ChangedFile`/`FileStatus` values the CLI parsers produce — `Sources/Pisaka/iOS/LibGit2Service.swift` (`#if os(iOS)`, `import libgit2`): `repositoryRoot` (discover → open → workdir), `changedFiles` (`git_status_list` with untracked-recurse + head→index/index→workdir rename detection, mapped to the same `FileStatus` precedence `GitStatusParser` uses — conflict → rename → untracked → add → delete → modified), `headContents` (HEAD-tree blob via `git_revparse_single`/`git_object_peel`/`git_tree_entry_bypath`), and `blob(stage:path:)` (merge-index entry via `git_index_get_bypath`, missing stage → `nil` like `git show :N:path`)
- [x] Implement `revert` matching the macOS service's per-`FileStatus` edge cases (checkout HEAD for modified/deleted, rm for added, delete for untracked, two-step rename with occupancy check, `PartialRevertError` on between-steps failure) — `.modified`/`.deleted`/`.conflicted` → force `git_checkout_tree` of the HEAD entry; `.added` → `git_index_remove_bypath` + index write + worktree delete (worktree-removed → `LibGit2InterruptedRevert`, the iOS `PartialRevertError`); `.untracked` → worktree delete; `.renamed` → restore `oldPath` from HEAD then unstage+remove the new path, with an `lstat`-based occupancy refusal and `LibGit2InterruptedRevert` reporting the paths already changed on a between-steps failure. (The macOS CLI's extra case-only-rename / hard-link disambiguation is a workaround for `git checkout`+`git rm` being two non-atomic *processes*; the in-process libgit2 index write does not hit that corner — recorded in the source doc comment.) The Log methods (`commits` is the one protocol-required-without-default; `references`/`commitChanges`/`fileContents` are defaulted) keep a `[]`/default placeholder until Phase 3 (Task 9), and `stage`/`stageRemoval` keep their no-op defaults until Phase 4 (Task 10)
