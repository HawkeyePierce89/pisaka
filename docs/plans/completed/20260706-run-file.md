# Run File — run the current file in the embedded terminal (macOS)

## Overview

Add the ability to run the editor's current file in a new embedded-terminal
session. macOS-only (iOS has no PTY/processes). Triggers: a "Run" item in the
project-tree file context menu, and ⌘R for the active tab. All
command/directory/quoting resolution is pure, testable, and lives in
`PisakaCore`; the view layer
(`TerminalSession`/`TerminalSessionsModel`/`PisakaApp`/`ProjectTreeView`) stays
thin and untested, under `#if os(macOS)`.

## Context

- Create: `Sources/PisakaCore/RunCommand.swift` — pure resolver (Foundation-only).
- Create: `Tests/PisakaCoreTests/RunCommandTests.swift`.
- Modify: `Sources/Pisaka/TerminalSession.swift` — add `run(command:)` via
  `terminalView.send(txt:)` (API confirmed: `send(txt: String)` on Apple
  `TerminalView`).
- Modify: `Sources/Pisaka/TerminalSessionsModel.swift` — `runFile(...)` +
  `runSessions` binding + cleanup in `close(id:)`.
- Modify: `Sources/Pisaka/PisakaApp.swift` — `runFile(url:)` handler,
  `CommandMenu("Run")` with ⌘R, thread `onRun` through
  `ContentView`/`ProjectTreeView`, save the dirty tab before running.
- Modify: `Sources/Pisaka/ContentView.swift` — thread the new `onRun` callback
  (like `onOpenFile`/`onNewFile`).
- Modify: `Sources/Pisaka/ProjectTreeView.swift` — "Run" item in the file-row
  context menu when `RunCommand.canRun`.
- Related patterns: `TerminalLaunch` (Core pure + view layer),
  `FileIcon`/`SyntaxLanguage` (extension→map resolution), callback params with
  default no-op (`onOpenFile`, `onNewFile`, …), `PlatformFeedback.warning()` +
  `PlatformAlert.presentMessage(...)`.
- Dependencies: none new. SwiftTerm is already linked.

- `swift test` is the fast gate for Core; the app-target build is verified
