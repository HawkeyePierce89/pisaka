# Run Test — per-file test runner

## Overview

Add a "Run Test" feature mirroring the existing "Run File": from a file's context menu (project tree) or a Run → Run Test menu item (⌘U), detect the project's test runner for the file's language and execute a per-file test command in a dedicated embedded-terminal session. All detection/command logic is pure and lives in PisakaCore (`TestCommand` + `ProjectTestEvidence`); the view layer stays thin. macOS-only (`#if os(macOS)`), like the terminal and Run File.

## Context

- Files involved:
  - Core (new): `Sources/PisakaCore/ShellQuote.swift`, `Sources/PisakaCore/TestCommand.swift` (contains `ProjectTestEvidence`).
  - Core (modify): `Sources/PisakaCore/RunCommand.swift` — reuse `ShellQuote` instead of its private `shellQuoted`.
  - Core tests (new): `Tests/PisakaCoreTests/TestCommandTests.swift`, `Tests/PisakaCoreTests/ShellQuoteTests.swift`.
  - View (modify): `Sources/Pisaka/TerminalSessionsModel.swift` (parameterize session key, add `testFile`), `Sources/Pisaka/PisakaApp.swift` (`testFile(url:)`, Run → Run Test ⌘U, evidence assembly, `onRunTest` wiring), `Sources/Pisaka/ContentView.swift` (thread `onRunTest`), `Sources/Pisaka/ProjectTreeView.swift` (file-row "Run Test" item).
- Related patterns: `RunCommand`/`TerminalLaunch` (pure enum + extension map), `FileIcon`/`SyntaxLanguage` (extension→value maps), the `onRun` callback threaded `PisakaApp → ContentView → ProjectTreeView`, `runFile(url:)`'s revert-gate + save-dirty-buffer flow.
- Dependencies: none. PisakaCore stays Foundation-only and dependency-free; all view files under `#if os(macOS)`.

## Development Approach

- **Testing approach**: TDD for the Core tasks (Task 1–2) — the design already enumerates the cases; write the tests first, then the resolver. Regular for the view tasks (Task 3–5), which hold no testable domain logic (verified by build).
- Keep all decision logic in Core; the view layer only assembles evidence, gates, and hands off.
- Complete each task fully (build + tests green) before the next.
- **CRITICAL: every Core task ships new/updated tests; all tests must pass before the next task.**
